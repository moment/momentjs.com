# Agent Instructions

## Repository Boundaries

- Treat this repository as the source for the Moment.js website, not as the
  source repository for the Moment.js libraries.
- Edit site content in `docs/`, `guides/`, `pages/`, `assets/`, `data/`, and
  `scripts/` as appropriate.
- Do not edit `build/`. It is generated by Eleventy and is gitignored.
- Moment and Moment Timezone are installed as pinned npm packages. Update their
  exact versions in `package.json` and regenerate `pnpm-lock.yaml` when changing
  the library versions published by the site.
- Preserve unrelated working-tree changes.

## Toolchain

- If dependencies are missing, install them with:

  ```sh
  pnpm install
  ```

- Use pnpm scripts rather than invoking locally installed tools directly.
- Do not hand-edit `pnpm-lock.yaml`; regenerate it with pnpm when dependencies
  change.

## Source Conventions

- The site is generated by Eleventy. Handlebars templates under `pages/` consume
  Markdown fragments from `docs/` and `guides/`; static output goes to `build/`.
- Documentation and guide order is determined lexically by the two-digit
  prefixes on directories and files. Keep the `NN-name` naming pattern.
- Each documentation section uses `00-intro.md` to provide the section title.
  Every Markdown fragment needs YAML front matter with at least `title`.
  Documentation API entries commonly also define `version` and `signature`.
- Add Moment content under `docs/moment` or `guides/moment`, and Moment Timezone
  content under their corresponding `moment-timezone` directories.
- JavaScript fences in `README.md`, `docs/`, and `guides/` are executable
  doctests. Write examples that can run independently in the sandbox. If an
  example is intentionally incomplete or requires an external environment,
  place `<!-- skip-example -->` immediately before its fence rather than
  weakening the test runner.
- Follow the existing CommonJS style in build and data scripts. Match the style
  of the file being changed, especially in older files.
- Prettier intentionally excludes `pages/**/*.hbs`, selected test wrappers, and
  the lockfile. Preserve local formatting in excluded files.
- Keep changes focused. Do not modernize historical documentation examples or
  upstream library code unless required by the task.

## Validation

- Format only files changed by the task when practical, then run the repository
  checks. Avoid `pnpm format` in a dirty worktree because it rewrites the entire
  repository.
- Run `pnpm lint` for formatting and Markdown checks.
- Run `pnpm doctest` after changing Markdown examples or the doctest machinery.
- Run `pnpm build` after changing templates, assets, data loaders, build scripts,
  or dependencies.
- For a complete verification matching CI, run:

  ```sh
  pnpm lint
  pnpm build
  pnpm doctest
  ```

- A build uses the installed Moment and Moment Timezone packages for scripts,
  downloads, data, and displayed size information.
- Do not commit generated `build/` output.
